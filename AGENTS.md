# Working agreements

## Ask before acting

Check with me before running commands or writing code. Describe what you intend
to do and wait for my go-ahead. This applies to ordinary work, not just risky
or destructive operations — I want to approve the plan first.

Reading and investigating is fine: reading files, inspecting state, and
answering questions do not need approval.

## Never run git commands

Do not run any git command on your own — no `commit`, `add`, `push`, `checkout`,
`branch`, `status`, `diff`, or anything else. I run git myself.

Leave changes in the working tree and tell me what you changed. If you need
information that git would provide, ask me to run the command and paste the
output.

## Commit messages

When we finish a piece of work, write a commit message for me in this format:
a one-line summary, then a bulleted list of the details.

```
Short one-line summary of the change

- First specific change, and why
- Second specific change, and why
- Third specific change, and why
```

Write the message as text in your reply. Do not commit it.
